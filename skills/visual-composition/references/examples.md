# Decision examples

Read when a composition decision is ambiguous or when evaluating the skill. These are examples, not mandatory layouts or wording.

| Situation | Weak choice | Better choice and reason |
| --- | --- | --- |
| Source settings inside a vacancy-search app | “ПОИСКИ ВАКАНСИЙ” above “Источники”, followed by “Управляйте источниками” | Keep “Источники” and labeled fields. Add instructions only for a non-obvious format or consequence; repetition adds no orientation. |
| Same screen in multiple workspaces | Delete every overline to simplify the header | Preserve the workspace identifier if it distinguishes which data will change. Necessary context is not decoration. |
| Dense transactions workspace | Giant heading, four invented KPI cards, each filter in a separate panel | Compact title/actions, grouped filters, aligned data. Space supports comparison; metrics require a real task and data source. |
| Long payment identifier | Clip it with no way to inspect it, or break all words globally | Let the identifier wrap locally or expose a labeled detail/copy affordance. Preserve access to the full value without damaging prose. |
| Selected row reached with Tab | Reuse the selection fill as the only focus treatment | Keep selection fill and a distinguishable focus indicator. These states communicate different facts. |
| Dark form | Invert colors and lower all secondary text opacity | Map semantic color pairs and measure them in the actual state; readability is independent of aesthetic subtlety. |
| Small typography fix | Introduce a new brand palette and design document | Reuse tokens and fix the affected role only. The requested scope controls the work. |

Use the same comparison method for new cases: name the user's task, show the consequence of the weak choice, and justify the smallest adequate alternative.
